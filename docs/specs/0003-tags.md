# Spec — Tags

## Problem Statement

Notes are plain text with no way to group or filter them. The user wants to
attach keywords to a note and filter the list by them, without affecting
scheduling.

## Solution

From the user's perspective: type `#продукты` in a note's text and it becomes a
tag on that note (shown in `/list`, removable with `/untag`). Filter with
`/list --tag продукты`. Tags are independent of reminders and repeats.

## User Stories

1. As a user, I want to add `/add купить хлеб #продукты #сегодня`, so that tags
   are captured from the note's text.
2. As a user, I want tags to be shown on the note in `/list`, so that I can see
   what a note is about at a glance.
3. As a user, I want `/list --tag <тег>`, so that I can see only notes with that
   tag.
4. As a user, I want `/untag <id> <тег>`, so that I can remove a tag without
   deleting the note.
5. As a user, I want tags to be stored / matched case-insensitively, so that
   `#Продукты` and `--tag продукты` match.

## Implementation Decisions

- **Schema**: add `tags TEXT[]` (default `'{}'`) to `notes` via `ALTER TABLE ...
  ADD COLUMN IF NOT EXISTS`. Tags are independent of `remind_at` / repeat.
- **Seam 1 (pure)**: `bot/tags.py::extract_tags(text) -> (body, tags)` — regex
  `(?:^|\s)#([A-Za-z0-9_-А-Яа-яЁё]+)`, tags lowercased and deduped, matched span
  replaced with a space and collapsed.
- **Seam 2 (DB)**: `add_note(..., tags)`, `add_tag(note_id, tag)`,
  `remove_tag(note_id, tag)` and `list_by_tag(tag)` (`WHERE $1 = ANY(tags)`).
  Tags are lowercased on write.
- **Handlers**: `/add` runs `extract_tags` on the cleaned body after reminder
  parsing; `/list` shows `🏷` markers and accepts `--tag <тег>`; `/untag <id>
  <тег>` removes a tag.
- Existing notes get empty tags; no data migration needed.

## Testing Decisions

- Unit test `extract_tags` (multiple tags, dedupe, lower-case, punctuation, no
  tags).
- Integration test against PostgreSQL: add note with tags, `list_by_tag`,
  `add_tag` append, `remove_tag`, verify tag is independent of reminder.

## Out of Scope

- Tag rename/merge or per-tag CRUD UI beyond `/untag`.
- Editing tags via the edit flow (uses `/untag`).
- Search by tag (covered by the Search feature, `/search #tag`).
